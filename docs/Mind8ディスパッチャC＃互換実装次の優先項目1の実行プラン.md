# Mind8ディスパッチャ C#互換実装 次の優先項目1の実行プラン

## 目的

C版のC関数番号表とC#の `SetupCsFunctions()` の登録を機械的かつ意味的に照合し、未登録・重複・誤割当てを特定する。C#にC版と同じ番号体系が反映されているかを、後続の互換実装とテストの基準として確定する。

## 対象

- C版: `C:\developments\vscode\mind8kernel\c_words.tbl`、`c_words.def`、対象カーネルの選択設定と該当C関数実装
- C#版: `CsFunctions.cs` の `SetupCsFunctions()` と、登録先メソッドを定義する `CsFunctions*.cs`
- 記録先: `docs/Mind8ディスパッチャC＃互換実装の実装状況.md`

## 作業手順

1. 通常ユーザーカーネルを基準にし、C版の番号・関数名を `c_words.tbl` から抽出する。先頭の予約番号とテーブル終端も明示する。
2. `SetupCsFunctions()` の全 `csFuncs[index] = method` 登録を抽出し、登録番号・メソッド名の一覧にする。
3. 番号をキーに両一覧を比較し、「一致」「C版にありC#未登録」「C#にのみ登録」「同じ番号で別関数」「同一関数への複数番号」に分類する。
4. 重複・別関数割当て候補はCテーブル上のエイリアスと、該当C関数およびC#メソッドの処理を確認する。エイリアスとして意図された重複と誤割当てを区別する。
5. とくに `0x0060`～`0x0062` など、CとC#で近接する関数名が異なる箇所を個別確認する。事前確認で見つかった差分候補も、一覧比較と実装意味の確認が済むまでは確定不具合と断定しない。
6. 差分表と判断根拠を実装状況文書へ記録し、修正対象と未解決項目を分ける。関数本体の意味を確認せずに登録先だけを一括変更しない。
7. 照合結果からテーブル対応を検査する自動テストまたは再実行可能な検査スクリプトを用意する。

## 検証と完了条件

- C版の選択したテーブルの全エントリーが比較表に現れ、C#登録側の全エントリーも分類されている。
- 重複は「C版にも同じ番号・同じ関数の対応があるため許容」など、許容理由が明示されている。
- 別関数割当てと未登録には、互換性影響・対応方針・未解決理由のいずれかが記載されている。
- 対応検査を再実行でき、C#プロジェクトのビルドと検査が成功する。

## 依存・注意点

カーネル種別によりC版の `.tbl` / `.def` が変わるため、基準カーネルを固定してから照合する。番号一致だけでは動作互換を意味しないため、意味の確認にはC実装とC#ハンドラーも参照する。
