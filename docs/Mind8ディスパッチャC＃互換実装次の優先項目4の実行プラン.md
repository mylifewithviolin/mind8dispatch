# Mind8ディスパッチャ C#互換実装 次の優先項目4の実行プラン

## 目的

C版とC#版へ同じMCOを入力し、外部から観測できる実行結果を比較する回帰テストを整備する。関数の追加・修正のたびに、既存機能の互換性を再確認できる状態にする。

## 現状と対象

現状のワークスペース検索では専用テストプロジェクトやテストファイルは見つかっていません。C#の起動部は `hellolevel7.mco` を固定指定し、ディスパッチ中に診断トレースも出力しています。

- C#版: `mind8dispatch.csproj`、`Mind8Dispatch.cs`、`Dispatcher.cs`、各 `CsFunctions*.cs`、既存の `hello*.mco` とレベル別サンプル
- C版: `mind8kernel` のユーザーカーネル構成、ビルド手順、対応する同一入力MCO
- 成果物: .NET 8の自動テスト、固定テスト入力、期待値またはC版基準結果、実行手順

## 作業手順

1. 比較対象となるC版カーネルの構成・ビルド方法・実行方法を確定し、同じMCOをC版とC#版へ渡せるようにする。C版をこの環境で構築できない場合は、再現可能な基準出力を別途生成・保管する方法を決める。
2. テストプロジェクトを追加し、MCOファイル名や出力先をテストから指定できる起動経路を作る。標準出力の比較を妨げるデバッグトレースは、無効化または別ストリームへ分離する。
3. 初期テストとして既存のhello系MCOから短く決定的な入力を選び、C版の標準出力・終了コードを基準データとして固定する。入力ファイルの由来と生成条件も記録する。
4. テスト観測値を定義する。標準出力と終了コードを必須とし、必要に応じてデータスタック・リターンスタック・対象データ領域・実行命令数などをテスト用インターフェースから取得する。
5. 互換機能をC関数番号・Mind単語またはシナリオ単位に分類し、対応実装がある範囲からC/C#差分テストを追加する。エンディアンや不正MCOはローダーの単体テストとして分ける。
6. 比較時は改行、文字コード、数値表記、環境依存値を仕様に基づいて正規化する。意味のある差を隠す正規化は行わず、差分時に入力、C版結果、C#版結果を判別できるようにする。
7. ローカル実行手順と、利用可能ならCIでの実行を文書化し、関数追加時のテスト追加ルールを実装状況文書へ反映する。

## 検証と完了条件

- テスト実行時にC版・C#版で同一の入力MCOを使用していることを確認できる。
- 少なくとも一つの決定的なhello系プログラムで、標準出力と終了コードがC版と一致する。
- 比較対象となる対応済み機能がテスト名から分かり、失敗時に差分と入力を追跡できる。
- 失敗するMCOやローダー条件のテストが正常系と分離され、安全に拒否されることを確認できる。
- テスト一式を一つのコマンドで再実行でき、通常の.NET 8ビルドとともに成功する。

## 依存・注意点

項目1の関数番号照合と項目2・3のローダー・制御フロー整備を段階的にテスト対象へ取り込む。C版のビルド環境やテスト用シリアル番号が異なる場合は、その差を明記して基準結果を固定する。未実装の関数を通る入力を、全面互換の証明として扱わない。
