# Mind8ディスパッチャ C実装概要

## 対象と構成

本書は `C:\developments\vscode\mind8kernel` のソースを読み、Mind8ランタイムの中間コード読込みとディスパッチの構造をまとめたものです。通常カーネルの構成は `kernel.c` がコンパイル時の設定を定義し、実装本体の `kerbody.c` をインクルードします。コンパイラ用などの別構成は `compker.c` などから同じ本体を異なる設定で組み立てます。

| ソース | 役割 |
| --- | --- |
| `kernel.c` / `compker.c` | カーネルの用途・機能をコンパイル時に選択し、`kerbody.c` を取り込む |
| `kerbody.c` | ポインター定義、関数テーブル、ランタイム処理群を一つの翻訳単位にまとめる |
| `kermain.c` | `.mco` の準備、メモリー領域の確保、実行開始を担当する |
| `dispatch.c` | 中間コードを読み、C関数またはMind単語へ制御を移す |
| `c_words.def` / `c_words.tbl` | C関数の宣言と、中間コード番号から関数への対応を定義する |
| `ptrdef.c` / `ptrmacro.def` | Mコード、データ、スタックなどのポインター表現と操作を定義する |

`kerbody.c` は `dispatch.c`、`kermain.c`、`compword.c`、`0ker.c`、`1ker.c`、`2ker*.c`、`3ker.c`、`4ker.c` などをインクルードします。したがって、実際に有効な関数群やシステム機能は、選択されたカーネル設定にも依存します。

## 起動とMCO読込み

通常カーネルでは `execute_main_word()` が `setupForDispatch()` を呼び、ロードと領域準備を行った後にデータスタックとリターンスタックを初期化します。実行開始位置はMコード領域のバイトオフセット `0x70` です。

`setupForDispatch()` の主な処理は次のとおりです。

1. ホストのエンディアンを調べ、MCOのエンディアン情報との違いを判定する。
2. 入力名に必要なら `.mco` を付加してファイルを開く。
3. ファイル末尾の32バイトのMコード情報を読み、`MC`マーク、Mコード形式のメジャーバージョン、ランタイム番号、シリアル番号を確認する。
4. 必要な場合はMコード情報、Mコード本体、LOCテーブルのバイト順を変換する。
5. Mコード本体とLOCテーブルを読み込む。LOCテーブルの各ワード位置は、Mコード領域の基準アドレスからの位置に調整する。
6. MCO情報に記録されたサイズに従い、データ領域と二つのスタック領域を確保して初期化する。

Unix構成ではファイル権限も確認します。読込み、確保、形式確認などのエラーは、カーネルの出力・終了処理へ送られます。

## ディスパッチ方式

`dispatcher()` は `FETCH_MCODE` で16ビットの命令を順に取得し、最上位ビットで命令種別を判定します。

| 命令 | 動作 |
| --- | --- |
| 最上位ビットが0 | 命令値をC関数番号として `C_Words_Addr[mcode]()` を呼び出す |
| 最上位ビットが1 | 下位15ビットをMind単語番号として扱い、現在のMコード位置をリターンスタックへ保存してLOCテーブルの位置へ移る |

Mind単語の復帰やデータ操作、条件分岐などは、各C関数およびポインタ・スタック用マクロが担います。ディスパッチャは `setjmp()` を使って再開点を設けます。C関数から `longjmp()` で戻った値が通常再開を示す場合はループを続け、終了を示す値の場合はディスパッチを終えます。

## C関数番号テーブル

`kerbody.c` はC関数ポインターの配列 `C_Words_Addr` を定義します。先頭の `0x0000`～`0x000F` はNULLの予約領域で、実際の番号は `0x0010` から始まります。通常のコンソールカーネルでは `c_words.tbl` が配列の初期化子として取り込まれ、`c_words.def` が対応する関数を宣言します。コンパイラ用、GUI用、CGI用などは別の `.tbl` / `.def` を選択する場合があります。

通常テーブルには、実行制御・スタック操作、アドレス計算、変数の読書き、定数、表示、条件分岐、算術・論理演算、文字列操作、入出力、OS機能などの番号が並びます。番号ごとの実装は複数のCソースに分かれています。テーブルの番号が中間コードとABI上の対応を定めるため、番号の変更や別テーブルとの混用は互換性に影響します。

- `c_words.tbl` は関数番号と関数名の対応を確認する基準ですが、各関数の動作の詳細は対応するC実装とポインタ・スタックマクロを併せて確認する必要があります。
