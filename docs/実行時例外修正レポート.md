# 実行時例外修正レポート

## 対象と結果

- 対象: シリアル番号46のサンプルMCOをC#ディスパッチャで実行すると発生する実行時例外。
- 報告された経路: `StackPointer.PopUl()` → `ZzWriteWvarLocal()` → `Dispatch()`。
- 結果: リポジトリ内の全10個のサンプルMCOを変更せず実行し、`Hello by mind8` の出力と終了コード0を確認した。
- 回帰テスト: **28/28件成功**。

## 原因

### 1. 局所変数のオフセット単位の誤り

MCO内の局所変数オフセットは、C実装の
`(UCHAR *)RstackPointer + FETCH_MCODE` に対応するバイト数である。
従来のC#実装は、その値を4バイト単位のスタック要素数として扱っていた。

そのため、局所変数への書き込み位置がずれ、保存された戻り先を破壊する場合があった。
今回の環境で修正前に再現した既定サンプルでは、壊れた戻り先から想定外の命令位置へ移動し、
未登録関数の呼び出しによる `NullReferenceException` も発生した。
報告された `PopUl()` の配列範囲外例外だけを抑えても、この破壊は解消しない。

### 2. 局所変数へのアクセスによるリターンスタックの移動

64ビット値・文字列情報の局所読み書きでは、`MoveStackPointer()` や `PopUl()` を使って
アクセス先を選んでいた。この処理は局所変数を参照するだけでなく、
呼び出しフレームのスタックポインタまで変えてしまっていた。

### 3. 書き込み幅とアンダーフロー検出の不備

- 16ビット値の書き込みで、2バイトの変換結果から4バイトをコピーする処理があった。
- `stackIndex - stackSize < 0` は符号なし整数の減算であり、
  空スタックからの取り出しを正しく検出できなかった。
  取り出し後にインデックスが巻き戻り、後続の配列参照が範囲外になる。

### 4. 表示処理に到達する前の未登録命令

局所変数処理を修正すると、既定の段階別サンプルは表示まで進んだ。
一方、[hello.mco](../hello.mco) の起動処理は、
Ctrl+Cの有効化と標準入出力のバイナリモード設定を使用しており、
それらの命令が関数テーブルに登録されていなかった。

## 修正内容

| ファイル | 修正 |
| --- | --- |
| [StackPointer.cs](../StackPointer.cs) | バイトオフセットとアクセス幅を受け取る `ReadLocal()` / `WriteLocal()` を追加。スタック要素の配置方向と要素内のバイト順を分けて扱い、スタックポインタを動かさず読み書きする。範囲外アクセスは明示的な例外とする。 |
| [StackPointer.cs](../StackPointer.cs) | `PopUb()` / `PopUs()` / `PopUl()` の空スタック判定を減算前の比較に変更。不正な取り出しは状態を変更する前に `InvalidOperationException` を送出する。 |
| [CsFunctionsCompword.cs](../CsFunctionsCompword.cs) | 局所読み出し `0x0053`～`0x0058`、局所書き込み `0x0069`～`0x006E` をバイト単位アクセスへ変更。1/2/4バイトの幅、64ビット値・文字列情報の2要素の順序、戻り先を保持する。 |
| [CsFunctions.cs](../CsFunctions.cs) | 関数テーブルを `0x0298` まで拡張し、起動処理に必要な命令を登録。 |
| [CsFunctions3ker.cs](../CsFunctions3ker.cs) | `0x0268` は対話コンソールのCtrl+C処理を有効化。`0x0296` / `0x0297` はWindows CRTのバイナリ/テキストモード定数を返す。`0x0298` は引数を取り出してWindows CRTの `_setmode()` を呼び、失敗を例外で通知する。 |
| [Dispatcher.cs](../Dispatcher.cs) | 未登録またはテーブル範囲外の命令は、命令番号とMCO内のバイト位置を含む `NotSupportedException` にする。未実装命令を無視して続行しない。 |
| [tests/Program.cs](../tests/Program.cs) | 局所変数・空スタック・未実装命令の回帰テスト、および全サンプルを別プロセスで実行するテストを追加。 |

例外を握りつぶしたり、スタック不足をゼロ値で補って実行を続けたりする修正ではない。
局所変数アクセス時の単位、メモリ配置、スタック状態の扱いを修正した。

## 検証

リポジトリのルートで次を実行した。

```powershell
dotnet build .\mind8dispatch.csproj --no-restore --nologo
dotnet run --no-restore --project .\tests\McodeLoaderTests.csproj
```

ビルド成功を確認し、最終の回帰テスト結果は次のとおり。

```text
28/28 tests passed
```

### 局所変数の回帰テスト

- バイト単位のオフセット、非整列アクセス、隣接バイトの保持。
- 1/2/4バイトの局所書き込み・読み出し命令の実行結果。
- 64ビット値・文字列情報のメモリ配置と読み出し順序。
- 読み書きの前後でのリターンスタックポインタと戻り先の保持。
- 空スタックからの取り出しが明示的に失敗し、スタック状態を変えないこと。
- 未実装命令のエラーに命令番号と位置が含まれること。
- 既存のローダー、エンディアン変換、スタックリセット、終了コードの各テスト。

### C版との比較

既存の参照Cカーネルはシリアル番号42であり、46のMCOをそのまま渡すと
`Serial number missmatch` で終了する。
比較テストでは、**参照C版に渡す一時コピーのみ**シリアル番号を42に変更する。
C#側は元の46のサンプルをそのまま実行する。
この条件で `hello.mco` の標準出力と終了コードがC版と一致することを確認した。
リポジトリ内のサンプルファイルおよびC#ランタイムのシリアル番号46は変更していない。

## 適用範囲

今回の確認対象はWindows上の全10個のサンプルと上記の回帰テストであり、
Mindの全命令を実装・検証したという意味ではない。
ファイルモード設定命令はWindows CRTに依存し、Windows以外で呼ばれた場合は
`PlatformNotSupportedException` を送出する。
既存の命令トレースは引き続き標準エラーへ出力される。
