# Mind8ディスパッチャ C#互換実装 次の優先項目3の完了レポート

## 結果

C版 `setjmp` / `longjmp` によるディスパッチ再開・終了制御を確認し、C#側の制御ループをC版の戻り値条件に合わせました。通常再開、ディスパッチ終了、プログラム終了を別経路として扱い、スタック状態・命令位置・終了コードをテストしました。

## C版との照合

- `dispatch.c` の `dispatcher()` は `setjmp(RESTARTENV)` の初回値0で命令ループに入り、戻り値が2でない限りディスパッチを継続します。コメント上、値1は通常再開、値2はディスパッチ終了です。
- `compword.c` の `stackReset()` は `resetDataStackPointer()`、`resetRetnStackPointer()` の後に `longjmp(RESTARTENV, 1)` を呼びます。スタックリセット関数は `ptrdef.c` でそれぞれ `DataStackBase[RestartEnvCount]` と `RetnStackBase` にポインターを戻します。
- 同ファイルの `finish_dispatcher()` と `c_stack_data_no()` は `longjmp(RESTARTENV, 2)` を呼びます。
- `FETCH_MCODE` はC関数呼出しより先に命令位置を進めます。`stackReset()` はMコード位置を変更しないため、再開後は次命令から実行する必要があります。

## 実装内容

- `Dispatcher.Dispatch()` を再開可能な明示ループにし、`LongJmp(2)` はディスパッチ終了、それ以外は再開として扱うようにしました。これはC版の `retcode != 2` 条件と一致します。
- `ExitModule` は `LongJmp` と別に捕捉し、緊急終了コードおよび指定されたプロセス終了コードをそのまま返すようにしました。
- `StackReset()` は両スタックをリセットしてから再開例外を送出します。スタックリセット処理は呼び出し側に一元化されており、ディスパッチャ側で二重リセットしません。
- スタックリセット後の次命令実行、スタック検査、ディスパッチ終了、緊急終了、プロセス終了コード保持を単体テストに追加しました。また、合成MCOを読み込んで同じ再開シナリオを実行する統合テストを追加しました。
