# Mind8ディスパッチャ C#互換実装 次の優先項目4の完了レポート

## 結果

C版とC#版へ同じMCOを渡し、標準出力と終了コードを比較する回帰テストを追加しました。ローダーの正常系・異常系と、ディスパッチ再開・終了のテストも同じテストプロジェクトにまとめ、単一コマンドで実行できることを確認しました。

実行時に既存のhello出力比較テストが失敗し、比較対象を調査する過程で32-bit Mコード読み取りと、ファイル名・MCode内文字列の扱いに互換性上の不具合を確認しました。関連する修正と回帰テストも加えた結果、全21テストが成功しています。

## 実装内容

- `tests/McodeLoaderTests.csproj` をテスト実行プロジェクトとして使用し、ローダー、実行制御、C/C#出力比較のテストを `tests/Program.cs` に統合しました。
- hello比較テストは、`hello.mco` のコピーを一時ファイルとして作成し、テスト用にSerial番号を42へ合わせた同一ファイルをC#版とC版の両方に渡します。テストはC#とCの標準出力および終了コードを比較します。
- C#側の診断トレースは標準エラーへ分離されており、標準出力の比較を妨げません。Cカーネルの標準エラーも取得し、比較失敗時の診断に含めます。
- Cカーネル実行ファイルが存在しない環境では、helloの期待出力と終了コードを使う代替確認へ切り替わります。この環境ではCカーネル実行ファイルが存在したため、代替確認ではなく実バイナリとの比較を実施しました。
- `MCodePointer.FetchMcodeInt()` が4バイト値の先頭2バイトしか読み取っていなかった不具合を修正しました。
- `CmcodeFullFilename()` がunmanaged pointerをMCode領域のoffsetとして扱っていた不整合を修正し、ファイル名をMCode領域へ追加してoffsetを渡すようにしました。バイト検索は指定長の配列を先に確保せず、対象バイトに到達するまで走査します。
- 32-bit Mコード値の取得、NUL終端までのバイト検索、hello出力比較の回帰テストを追加しました。

## 検証結果

- 実行コマンド: `dotnet run --no-restore --project tests\McodeLoaderTests.csproj`
- 結果: **21/21テスト成功**。テストプロジェクトと参照先の.NET 8アプリケーションもこの実行でビルドされました。
- hello比較: C#版・C版ともに標準出力は `Hello by mind8`、終了コードは `0` で一致しました。
- ローダーの拡張子解決、メタデータ検査、破損・切詰め入力の拒否、ビッグエンディアン変換を確認しました。
- スタックリセット後の次命令からの再開、両スタックの状態、ディスパッチ終了、緊急終了コードとプロセス終了コードの保持を確認しました。
- 変更したC#ソースにVS Codeの診断エラーはありません。CRLFを考慮した差分チェックも成功しました。

## 適用範囲・注意点

- 比較に使ったC実行ファイルは `mind8kernel/obj/kernel.exe` に既存のものを使用しました。このタスクではCカーネルを再ビルドしていないため、Cソースの現在の状態と実行バイナリが一致することまでは確認していません。
- 同梱 `hello.mco` のSerialは現在のC#ランタイム設定と異なるため、元ファイルは変更せず、一時コピーのヘッダーだけをテスト用Serial 42へ変更して両実装に渡しています。
- Cカーネルがない環境での代替テストは固定期待値との比較であり、C/C#実バイナリ間の比較ではありません。
- 現在のC/C#差分テストはhelloシナリオが中心です。すべての対応済みC関数・Mind単語を網羅した比較テストではなく、未実装機能を含むプログラム全体の互換性を示すものではありません。
- CIでのテスト実行設定、およびテスト追加ルールの `docs/Mind8ディスパッチャC＃互換実装の実装状況.md` への反映は未実施です。
