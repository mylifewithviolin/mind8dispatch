# Mind8ディスパッチャ C#互換実装 次の優先項目2の実行プラン

## 目的

C版 `kermain.c` のMCOファイル解決、Mコード情報の検証、エンディアン判定と変換にC#のロード処理を合わせ、不正・非互換な入力を実行前に一貫して拒否できるようにする。

## 対象

- C版: `kermain.c` の `openMcodeFile()`、`readMcodeInfoTable()`、`checkMyEndian()`、`checkNeedToBeSwapped()`、`swapMcodeInfoTable()`、`swapMcode()`、`swapLoctable()`、`setupForDispatch()`。関連する `kernel.def`、`serialno*.def`、`runtno*.c` の定数・値も確認する。
- C#版: `Dispatcher.cs` の `SetupForDispatch()`、`SetMcodeInfo()`、MCO情報構造体とファイル名を渡す `Mind8Dispatch.cs` の起動部
- 将来の検証: 項目4の差分テスト

## 作業手順

1. C版の対象カーネルを固定し、MCO末尾の32バイト構造体、バージョン情報のビット位置、ランタイム番号、シリアル番号、エンディアンフラグ、Mコード・LOCテーブルの読み込み順を仕様表にする。
2. C版のファイル名規則を確認する。拡張子の補完・大文字小文字の扱い・相対パス・構成依存の検索先と、C#の現状との差を整理する。
3. ロード処理を段階化する。ファイル解決、サイズと完全読込みの検証、MCO情報のデコードと全フィールド検査、バイト順補正、MコードとLOCテーブル読込みの順に責務を分ける。
4. `BitConverter` に暗黙依存しない明示的なバイト順処理を導入し、ヘッダー値・Mコード・LOC値を同じエンディアン規則で解釈する。C版固有のMコード内エンディアン情報テーブルの変換方式を調べ、単純な全ワード反転に置き換えない。
5. ファイル名は呼び出し側から指定可能にし、C版で必要な拡張子規則を実装する。GUI/CGI等の構成固有検索先をC#でサポートするかは、用途を決めて別途明示する。
6. エラーを入力不備、互換性不一致、I/O失敗に分類し、呼び出し側に予測可能な結果として返す。部分読込み、サイズ超過、LOCテーブルサイズ不整合、短いファイルを処理する。
7. 有効なMCOと破損・境界値を作り、各検査が意図どおり受理・拒否するテストを追加する。

## 検証と完了条件

- `MC`マークに加え、C版と同じバージョン、ランタイム番号、シリアル番号、エンディアン適合性を検査する。
- 対応するエンディアンのMCOで、ヘッダー、Mコード、LOC値がC版と同じ論理値になる。
- 拡張子の有無・大文字小文字・不在ファイルに対する動作が仕様化され、テストされている。
- 短いファイル、サイズ不整合、不正なマーク、非対応バージョン・ランタイム・シリアル、変換テーブル不整合を安全に拒否する。
- 既存の代表MCOを用いたC版との比較が成功し、.NET 8プロジェクトのビルドとローダーテストが通る。

## 依存・注意点

項目1で基準とするカーネル構成を定めてから、その構成に対応するランタイム番号・シリアル番号・MCO仕様を選ぶ。C版の構成依存のファイル検索やエラー表示をそのまま移すのではなく、C#アプリケーションで必要な振る舞いを先に決める。
