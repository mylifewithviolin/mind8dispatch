# Mind8ディスパッチャ C#互換実装 次の優先項目3の実行プラン

## 目的

C版 `dispatch.c` の `setjmp` / `longjmp` による再開・終了制御をC#の例外制御で正確に再現する。通常再開、ディスパッチ終了、プログラム終了を混同せず、各ケースでスタックと命令位置が正しく保たれるようにする。

## 対象

- C版: `dispatch.c` の `dispatcher()`、`0ker.c` 等で定義される再開・終了用C関数、`resetDataStackPointer()` / `resetRetnStackPointer()` の実装
- C#版: `Dispatcher.cs` の `Dispatch()` と `LongJmp` / `ExitModule`、`CsFunctions*.cs` の `StackReset()`、`FinishDispatcher()`、`C_stack_data_no()`、終了系ハンドラー

## 作業手順

1. C版で `setjmp()` の初回戻り値と、各 `longjmp()` の戻り値が意味する制御を表にする。戻り値1の再開時に、命令ポインターと両スタックがどうなるかを関数実装まで追跡する。
2. C#側の制御を「実行継続」「初期状態へ戻して再開」「ディスパッチ終了」「プログラム終了」に分け、それぞれの呼び出し元と必要な状態変更を定義する。
3. `Dispatch()` の処理を再開点を含む明示的な制御ループにする。再開用例外は適切な範囲で捕捉し、通常再開コードではC版と同じ初期化後に命令実行を再開、終了コードではディスパッチだけを抜ける。
4. `ExitModule` はディスパッチ再開例外から分離し、プログラム終了コードが誤って再開や正常終了へ変換されないようにする。
5. 二重リセット、スタック上の戻り番地、再開時のMコード位置など、C版とC#版の状態遷移を小さなテストで照合する。

## 検証と完了条件

- 通常再開要求後、C版と同じスタック初期状態・次の命令位置から実行を継続する。
- ディスパッチ終了要求は現在のディスパッチを一度だけ終了し、意図した戻り値を返す。
- プログラム終了要求は指定された終了コードを保ち、再開処理へ入らない。
- 各制御経路でハンドラーが二重実行されず、スタックの不整合や制御ループの継続・早期終了がないことを単体テストとMCO実行で確認する。
- C版と同じ再開・終了シナリオを実行した比較テストと.NET 8のビルドが通る。

## 依存・注意点

C版の各 `longjmp()` 呼出し側が行うスタック操作を先に確定する。例外を捕捉してループを続けるだけでは互換にならない。戻り値1・2のどちらを投げるか、スタック初期化を呼出し側とディスパッチャ側のどちらが担うかを一箇所に定義する。
