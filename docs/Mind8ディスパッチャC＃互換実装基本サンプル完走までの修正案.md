# Mind8ディスパッチャ C# 互換実装 — 基本サンプル完走までの修正案

## 目的

`tests/fixtures` の5つのMCOをC#ディスパッチャで実行し、正常終了と標準出力の完全一致を確認する。
正解出力は `tests/fixtures/reference/*.stdout.txt` とし、比較時に末尾改行や全角空白を正規化しない。

## 現状確認

現行ディスパッチャのランタイムシリアル番号は46である。MCOのヘッダーを確認したところ、サンプル間でシリアル番号が異なる。

| サンプル | MCOシリアル | 現行版での実行 | 参照出力 |
| --- | ---: | --- | --- |
| `hello.mco` | 46 | 終了コード0、完全一致 | `hello.stdout.txt` |
| `variables.mco` | 46 | 終了コード0、完全一致 | `variables.stdout.txt` |
| `binarysearch.mco` | 42 | シリアル番号不一致で起動前に拒否 | `binarysearch.stdout.txt` |
| `bubblesort.mco` | 42 | シリアル番号不一致で起動前に拒否 | `bubblesort.stdout.txt` |
| `insertsort.mco` | 42 | シリアル番号不一致で起動前に拒否 | `insertsort.stdout.txt` |

後半3件については、一時コピーのヘッダーだけをシリアル番号46にした追加確認も行った。元のMCOと参照テキストは変更していない。起動後、未登録命令で停止し、参照出力の一部しか出力されなかった。

| サンプル | 最初に到達した未登録命令 | `c_words.tbl` 上の対応 | 停止時の標準出力 |
| --- | --- | --- | --- |
| `binarysearch.mco` | `0x00C9` | `zzBaiseidoHyouji`（10進数表示） | 「探索対象のボール数　」まで |
| `bubblesort.mco` | `0x00C4` | `zzKaigyou`（改行表示） | 「整列前　」まで |
| `insertsort.mco` | `0x0112` | `ookii`（大なり比較） | 出力なし |

現行の `SetupCsFunctions()` には表示命令 `0x00C1` はあるが、上表の3命令は登録されていない。したがって、シリアル番号の違いだけを解消しても完走しない。また、これらは実行時に最初に見つかった不足であり、後続命令にも未実装箇所が残る可能性がある。

## 修正方針

### 1. MCOとランタイムのシリアル番号を整合させる

**方針更新:** 以下の検討案より、末尾の「追記：正規版シリアル42への統一方針」を優先する。対象は正規版の通常コンソール用ランタイム10・シリアル42である。

`hello` / `variables` は46、探索・ソート3件は42である。シリアル番号はMCOとランタイムの互換性を示す値なので、動作確認なしに42を46へ書き換えて互換性があるように見せてはならない。

推奨順は次のとおり。

1. 可能なら各 `.src` を対象ランタイムのコンパイラ設定で再生成し、MCOのヘッダーとランタイムを同じシリアル番号にする。
2. シリアル42のMCOを現行C#ランタイムでもサポートすることが要件なら、C版の42と46のABI差・関数番号・呼び出し規約を確認し、C#側に明示的な互換性を実装する。42と46の両方を受け付けるだけの変更は、互換性の証明にはならない。
3. コンパイラが使えず、番号変更を試す場合は、元ファイルではなくテスト用コピーに限定する。ヘッダーのシリアル番号位置はファイル末尾から10バイト目、値はリトルエンディアンの2バイトである。変更前後の実行結果とABI確認を記録する。

この判断が終わるまでは、既存MCOのシリアル番号を一括変更しない。

### 2. 不足命令をC版の仕様に合わせて実装する

最初に確認できた命令を、次の順で実装する。

1. `0x00C4` 改行表示。C版と同じ改行位置・改行数にし、余分な空白や改行を加えない。
2. `0x00C9` 10進数表示。スタック上の値の幅、符号、表示幅、スタック消費をC版に合わせる。二桁表示を通常の整数表示に置き換えない。
3. `0x0112` 大なり比較。左右のオペランド順、スタック消費、条件分岐命令へ渡す結果をC版に合わせる。

実装仕様は命令名だけから推測せず、C版の関数本体とスタック操作を確認する。未登録命令を無視したり、既定値を返したりして実行を続ける修正は行わない。

### 3. 各サンプルを再実行し、次の不足を順に解消する

命令を追加するたびに3サンプルを再実行し、新たに停止した命令を特定する。特に次の動作をC版と照合する。

- **二分探索**: 箱の初期化、配列要素の読み書き、整数演算、等値・大小比較、分岐、繰り返し、数値・文字列・改行の表示。
- **バブルソート**: 外側・内側ループ、配列要素の比較と交換、一時値の保持、途中経過表示、桁幅を含む数値表示。
- **挿入ソート**: ループ、配列要素の比較とシフト、境界条件、途中経過表示、文字列変数と改行を含む出力。

停止命令番号とMCO内オフセットを記録し、必要な命令だけを実装する。各命令の実装後も、既に一致している `hello` と `variables` を回帰確認する。

### 4. 参照出力とのプロセス比較をテストに追加する

現在の `TestAllSampleOutputs()` は作業ディレクトリ直下のMCOを実行し、`Hello by mind8` を含むことを確認するテストである。`tests/fixtures` の5件について、参照テキストとの完全一致を検証するテストは別途必要。

各fixtureについて別プロセスで実行し、次を検査する。

- 終了コードが0である。
- 標準出力が対応する `tests/fixtures/reference/<name>.stdout.txt` と完全一致する。
- タイムアウトしない。
- 標準エラーにエラーが出ていないことを確認する。命令トレースを標準エラーへ出す設定の場合は、標準出力との混同を避け、エラー診断とトレースを区別する。

期待ファイルと出力の比較では `Trim()`、空白の正規化、改行変換を行わない。これにより、日本語の全角空白、二桁表示、行の順序、末尾改行の差を検出できる。

## 完了条件

- 5つのMCOそれぞれが、意図したシリアル番号・ランタイム設定でロードされる。
- 5件すべてがタイムアウトせず終了コード0で完走する。
- 各標準出力が対応する参照テキストとバイト単位で一致する。
- 既存のローダー・スタック回帰テスト、および `hello` / `variables` の一致が維持される。
- シリアル番号を調整した場合、その互換性の根拠と対象をテストまたは記録に残す。

## 追記：正規版シリアル42への統一方針

### 経緯と基準

C#ディスパッチャの開発時には、`C:\developments\vscode\mind8` 側でスタートアップのソースを修正し、起動時に処理する中間コードを減らしたMindランタイムを再ビルドしてシリアル番号を変更していた。シリアル46はその開発経緯によるもので、正規版の通常コンソール用ランタイムを基準とする今回の目標値ではない。

確認できた根拠は次のとおり。

- 正規版 `C:\pmind\kernel\serialno.def` は `SERIALNO 42`、開発版 `C:\developments\vscode\mind8\kernel\serialno.def` は `SERIALNO 46` である。
- 正規版 `C:\pmind\bin\showargs.mco`、`euc2sjis.mco`、`sjis2euc.mco` など、バージョン8・ランタイム10のMCOはシリアル42である。
- `C:\pmind\bin` にはランタイム60・シリアル19など別用途のMCOもある。すべてのMCOが42という意味ではなく、本計画は通常コンソール用ランタイム10を対象とする。
- `C:\pmind\file\console.src` と `C:\developments\vscode\mind8\file\console.src` は同一内容だった。一方、開発用の段階別スタートアップとして `C:\developments\vscode\mind8\filelevel7\conslevel7.src` が存在する。正規版スタートアップ全体の動作がC#側で実装済みということは、これらの確認だけでは判断できない。

### 改訂後の実装手順

1. [Dispatcher.cs](../Dispatcher.cs) の `SerialNumber` を **46から42へ変更**する。バージョン8、ランタイム10、シリアルの検査は維持し、46を無条件に受け入れる処理やヘッダー検査の無効化は行わない。
2. シリアル42の `binarysearch`、`bubblesort`、`insertsort` は元のMCOを変更せず実行する。正規版の起動・実行を基準に、不足命令やスタック・データ操作を前述の方針に従って実装する。先の46へのヘッダー書換えは調査用に限られ、実装後の合格条件には使わない。
3. シリアル46の `hello` と `variables` は、正規版のコンパイラ・通常コンソール用スタートアップを使って、それぞれの `.src` からシリアル42のMCOを再生成する。正規版の起動処理を含むことを確認し、ヘッダーだけを書き換えて済ませない。再生成後にバージョン8、ランタイム10、シリアル42を確認する。ビルド手順・使用したツール・成果物を記録し、出力を参照テキストと比較する。再生成の具体的なコマンドは未検証のため、正規版のビルド環境と手順を確認してから決定する。
4. 正規スタートアップでは簡略版より多くの命令が実行され得る。`hello` / `variables` を再生成後も、起動途中の未登録命令を順番に特定し、C版の実装と比較して追加する。シリアル変更のみで完走できるとは限らない。
5. [tests/Program.cs](../tests/Program.cs) の合成MCOを生成する `CreateMco()`、`TestExistingSample()`、`TestAllSampleOutputs()`、C版比較テストを42基準に見直す。特に既存のルート直下 `hello*.mco` は46のため、元ファイルを正常実行できるという旧テストは成立しなくなる。42のMCOで正常系を検証し、46は不一致として拒否されることも検証する。C版との比較は両実装に同じ正規版42のMCOを渡す。
6. 最後に5件を元の参照出力と比較し、終了コード0、タイムアウトなし、標準出力の完全一致を確認する。再生成した `hello` / `variables` についても、参照テキストを書き換えて差を隠さない。

この追記は修正計画であり、現時点でC#実装やfixtureのシリアル番号を変更したこと、または正規版スタートアップの完走を確認したことを意味しない。
