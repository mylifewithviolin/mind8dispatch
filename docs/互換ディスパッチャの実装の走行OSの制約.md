# 互換ディスパッチャの実装の走行OSの制約

## 結論

本リポジトリのC#版は `.NET 8` の汎用ターゲット（`net8.0`）で、Windows固有のGUIやネイティブポインターに全面依存する構成ではありません。そのため、.NET 8が動作する環境であれば、ディスパッチャの主要部分はWindows以外でもビルド・実行できる見込みです。Intel/AMD x64のLinuxやApple Silicon（ARM64）のmacOSも候補になります。

ただし、これは現時点でのコード構成からの見込みであり、完了レポートの検証はWindows上のものです。LinuxやmacOS、ARM64上で実行・テストした実績は同レポートにはありません。また、C関数番号 `0x0298` のファイルモード設定はWindows CRTの `_setmode()` に依存し、Windows以外では明示的に `PlatformNotSupportedException` になります。したがって、全MCOが各OSで無条件に同じように動くとはいえません。

## OS・CPU別の見込み

| 実行環境 | C#版の見込み | 主な条件・制約 |
| --- | --- | --- |
| Windows x64 | 基本環境。完了レポートでビルドとテスト実行を確認 | 報告された成功結果は、その時点のWindows環境とテスト対象に対するもの |
| Intel/AMD x64 Linux | 実行できる見込み | 対象ディストリビューションで利用可能な.NET 8 SDKまたはRuntimeが必要。`0x0298` を実行するMCOは非対応 |
| Apple Silicon（ARM64）macOS | 実行できる見込み | ARM64対応の.NET 8 SDKまたはRuntimeが必要。`0x0298` を実行するMCOは非対応 |
| Intel x64 macOS | .NET 8対応環境なら実行できる見込み | 対象OS・SDK/Runtimeの組み合わせを確認する。`0x0298` を実行するMCOは非対応 |
| その他のOS・CPU | 未評価 | .NET 8の対応状況に加え、エンディアン、ファイルAPI、実行するMCOの命令を個別に検証する必要がある |

「実行できる見込み」は、OS・CPUに依存しないC#/.NETの機能で実装された範囲についての判断です。表に記載した環境での実動作や全面互換を保証するものではありません。

## 移植性に関する根拠と制約

### .NETプロジェクト設定

アプリケーションとテストプロジェクトは `net8.0` を対象にし、特定OS・CPU向けの `RuntimeIdentifier` はプロジェクトファイルに固定されていません。実行ファイルのネイティブコードを直接扱う箇所を除けば、ファイル操作、配列、標準入出力、プロセス制御などは.NETのAPIを使用しています。通常のフレームワーク依存ビルドでは、実行先に対応する.NET環境が必要です。単一OS・CPU向けの自己完結型配布物を作る場合は、その環境に合わせたRID指定と個別ビルドが必要です。

### Windows専用のファイルモード命令

`CsFunctions3ker.cs` の `0x0298` は `ucrtbase.dll` の `_setmode()` をP/Invokeで呼びます。非Windows環境ではネイティブ関数を呼び出す前に `PlatformNotSupportedException` を送出する実装です。関連する `0x0296` と `0x0297` はモード定数をスタックに積む処理で、これらの命令だけで直ちにOS固有関数を呼ぶわけではありませんが、C版と同じファイルモード切替動作が他OSで提供されることを意味しません。

つまり、非Windows環境での可否はMCOがこの命令を実行するかにも左右されます。非Windows向けに同等動作を実現するなら、移植先の標準入出力・ファイルAPIに合わせた仕様決定と実装、およびC版との比較テストが必要です。未対応命令を使うMCOを、例外を無視して続行させることは互換性を保証しません。

### バイト順とCPUアーキテクチャ

ローダーはMCOのエンディアン情報とホストのバイト順を比較し、必要な変換を行う実装です。`BitConverter` によるデータアクセスもコード内で使われています。Intel x64と一般的なARM64環境はいずれもリトルエンディアンで動作するため、これらのCPU間ではエンディアン差が主要な障害になる可能性は低いと考えられます。ただし、異なるエンディアンのCPUや実行環境について、ここでのテスト実績はありません。

### C#実行系とC版リファレンスの違い

完了レポートはC#版とC版に同一の一時MCOを渡し、標準出力と終了コードを比較しています。C版リファレンスとして使われたのはWindows上の `mind8kernel/obj/kernel.exe` です。テストコードはそのファイルが存在しない場合、C版を起動せず、C#版の固定期待出力で確認します。

このため、LinuxやmacOSでテストを実行できたとしても、Windows用C実行ファイルとの比較がそのまま行われるわけではありません。各OSでC版カーネルをビルドできるなら、そのOS上のC版とC#版を比較するテストが望まれます。C版を用意できない環境では、固定期待値との比較は可能ですが、それはC/C#間の実バイナリ比較とは異なります。

## 完了レポートで確認された範囲

「Mind8ディスパッチャ C#互換実装 次の優先項目4の完了レポート」では、Windows環境で次が報告されています。

- `dotnet run --no-restore --project tests\McodeLoaderTests.csproj` によるテストが21件成功
- hello MCOの標準出力 `Hello by mind8` と終了コード `0` がC版・C#版で一致
- ローダー、ビッグエンディアン変換、ディスパッチ再開・終了などのテスト
- C版には既存のWindows実行ファイルを使用し、Cカーネル自体は再ビルドしていない

この結果はWindowsでの限定された検証です。Linux、Intel x64 Linux、Intel macOS、ARM64 macOSでのビルド・実行結果ではなく、C関数やMind単語を網羅した互換性の証明でもありません。

## 他OSで確認するときの手順

1. 対象OS・CPUに対応する.NET 8 SDKを用意し、ルートプロジェクトをビルドする。
2. `dotnet run --project tests/McodeLoaderTests.csproj` を実行し、テスト結果と失敗したMCO・命令番号を記録する。
3. サンプルMCOが対象OSで成功するか確認し、`0x0298` などOS依存命令を実行する場合は、その結果を独立して評価する。
4. 可能なら対象OS上でC版カーネルもビルドし、同一MCOの標準出力・終了コードをC#版と比較する。
5. Apple SiliconではARM64の.NET環境でテストし、x64エミュレーションでの結果と混同しない。
6. OSごとの検証結果を追加するまでは、配布説明で当該OS・CPUの動作を確認済みと表現しない。
