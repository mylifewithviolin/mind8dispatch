# Mind8ディスパッチャ C#互換実装 次の優先項目2の完了レポート

## 結果

通常ユーザーカーネルを基準にC#のMCOローダーを改修しました。C版のMCO識別情報検査、バイト順判定・変換、拡張子補完、完全読込み、主要なサイズ整合性確認を実装し、引数からMCOファイル名を指定できるようにしました。

## C版との照合結果

- `kernel.def`: MCO MajorVersion `8`、`BigEndianMcodeBit` `0x20`、`EndianInfoRatio` `8`
- `serialno.def`: SerialNo `42`
- `runtno.c`: RuntimeNo `10`
- C版はファイル末尾32バイトの情報を検査し、エンディアンが異なる場合はMCO内のEDI表を使ってMコード値を変換し、LOCの各32ビット値も変換します。
- C版のファイル名規則に合わせ、入力名に`.mco`がない場合は補完し、拡張子比較は大文字小文字を区別しません。

## 実装内容

- `Dispatcher.SetupForDispatch()` をファイル名解決、末尾ヘッダーの完全読込み、メタデータ検査、ペイロード境界検査、Mコード・LOC読込み、必要なエンディアン変換に整理しました。
- `BinaryPrimitives` による明示的なリトル／ビッグエンディアン読み出しを使い、ヘッダー値の解釈をホストのバイト順から分離しました。
- Version、Runtime、Serial、`MC`マーク、MAIN、Mコードサイズ、LOCサイズ、データサイズ、データスタック・リターンスタックサイズを検査します。MCOのペイロードが不足する場合、必要なEDI表が切り詰められている場合も拒否します。
- C版のEDI表の2ビット情報を用いて、16ビット値と32ビット値を選択的に変換します。LOCの32ビット値も変換します。
- `Mind8Dispatch.Main` はコマンドラインの第1引数をMCOパスとして使い、引数がなければ従来の `hellolevel7.mco` を使います。
- `tests/McodeLoaderTests.csproj` と `test MCO loader` タスクを追加しました。アプリ本体へのテストソース混入を避けるため、メインプロジェクトから `tests/**/*.cs` を除外しています。

## 検証結果

- VS Code `test MCO loader`: 12/12成功。拡張子補完、大文字拡張子、同梱MCOの互換ゲート、Version/Runtime/Serial/MAIN/LOCサイズ異常、短いファイル、ペイロード切詰め、EDI表切詰め、ビッグエンディアンのMコード・LOC変換を確認しました。
- VS Code `build`: 成功。`mind8dispatch.dll` を生成しました。
- 同梱 `hellolevel7.mco` はVersion 8 / Runtime 10 / Serial 46です。対象CユーザーカーネルはSerial 42のため、C版の互換条件に従い同梱ファイルを拒否することをテストで確認します。正常系ローダーは互換メタデータを持つ合成MCOで検証しています。

## 残課題・適用範囲

- C版のVersion、Runtime、Serial、EDI仕様をソース上の通常ユーザーカーネル設定から固定しています。コンパイラ用など別カーネルを対象とする場合は、別の識別値とテーブルを選ぶ仕組みが必要です。
- C版のCGI専用検索パス、UnixのMCO権限検査、Cランタイム固有の診断表示は移植していません。
- MCOファイル名はAPIとコマンドラインから指定できますが、C版の構成別サーチパス検索までは行いません。
- C#のLOCアクセスは配列内オフセット方式のままです。C版のポインター基準アドレス調整を模倣せず、読み込んだLOC値のエンディアンのみ変換します。
- MCO読み込み後のディスパッチ機能全体の互換性や、C版実行結果との比較はこの項目のテスト範囲外です。
