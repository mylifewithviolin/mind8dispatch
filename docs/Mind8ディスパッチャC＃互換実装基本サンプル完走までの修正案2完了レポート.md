# 基本サンプル完走までの修正案2 実行レポート

## 区切り1: 着手時の確認

- 正規コンソール用ランタイムはバージョン8、ランタイム10、シリアル42。現行C#実装と `hello` / `variables` のfixtureはシリアル46である。
- `binarysearch`、`bubblesort`、`insertsort` のfixtureはシリアル42。これらのMCOは変更せず実行する。
- 既存のコード、テスト、fixtureには未コミットの変更があるため、それらを保持して作業する。
- シリアル42への移行に伴い、シリアル46のルート直下サンプルを正常実行する従来のテストを見直す必要がある。
- 正規コンパイラの再生成手順と正規スタートアップで必要な命令は、以後の区切りで検証する。

## 区切り2: シリアル42への移行とfixture再生成

- [Dispatcher.cs](../Dispatcher.cs) のシリアル検査を42に変更し、合成MCOも42に変更した。シリアル46を拒否するテストを追加した。
- `hello.src` と `variables.src` の「を」と「表示」の間に区切りを追加した。正規コンパイラは区切りなしの元の記述を送り仮名のエラーとして拒否した。
- セッション内の作業ディレクトリに両ソースをShift-JISで作成し、`MLIBPATH=C:\pmind\lib`、`PATH` に `C:\pmind\bin` を設定したうえで、正規版 `mind.exe hello file` と `mind.exe variables file` を実行した。生成MCOを各fixtureに反映し、バージョン8・ランタイム10・シリアル42を確認した。
- 正規コンパイラが生成したそれぞれの実行ファイルを実行し、終了コード0、参照テキストとの文字列完全一致を確認した。3つの探索・整列MCOと参照テキストは変更していない。
- `dotnet build .\mind8dispatch.csproj --no-restore --nologo` は警告0、エラー0で成功した。シリアル42でのC#側のサンプル完走はまだ未確認であり、残るテストの移行と命令実装を続ける。

## 区切り3: 最初の未登録命令とシリアル回帰テスト

- `0x00C4` 改行、`0x00C9` 符号付き64ビット整数表示、`0x0112` 符号付き大なり比較を登録した。C版のスタック消費・値の順序を参照し、改行は参照ファイルと同じLFを出力する。
- 既存テストを42基準に移行し、開発版シリアル46を拒否するテスト、負数・比較順序のテストを追加した。C版比較はヘッダーを書き換えず同じ正規fixtureを使用するよう変更した。
- `dotnet run --no-restore --project .\tests\McodeLoaderTests.csproj` は30/31件成功。失敗1件は正規スタートアップの未登録命令 `0x01D5` によるもので、未解決として継続する。
- 次に停止した命令は、`hello` / `variables`: `0x01D5`、`binarysearch` / `bubblesort`: `0x0110`、`insertsort`: `0x00D6`。5件とも完走には至っていない。

## 区切り4: 数値・配列処理

- 小なり、論理積、偽判定、整数除算、8バイト配列要素の選択を追加した。配列添字は1から要素数までを検査する。
- 既存の8バイト間接読出しで同じ4バイトを2回読んでいた箇所、および整数演算が整数部でなく小数部を更新していた箇所を修正した。
- [tests/Program.cs](../tests/Program.cs) に配列境界、両ワード、真偽値、整数演算の回帰テストを追加した。ビルドは警告0、エラー0で成功した。
- 再実行では `bubblesort` が終了コード0で参照出力と文字列完全一致した。`binarysearch` は `0x0114` が未登録、`insertsort` は終了コード0だが出力不一致、`hello` / `variables` は正規スタートアップの `0x01D5` が未登録のままである。全件完了ではない。

## 区切り5: 探索・整列3件の完走

- 等値比較を追加し、文字列変数の読出しで長さとアドレスを区別できていなかった箇所を修正した。
- 正規スタートアップの文字列取出し `0x01D5` を追加し、Mコード領域とデータ領域の文字列を区別して読み出す処理を追加した。データ領域内の文字列実体の読出しも修正し、Shift-JISの2バイト文字を分断しない回帰テストを追加した。
- `binarysearch`、`bubblesort`、`insertsort` はそれぞれ終了コード0で、参照テキストと文字列完全一致した。
- `hello` / `variables` は新たに正規スタートアップの未登録命令 `0x01DD` で停止するため、継続して対応する。ビルドは警告0、エラー0で成功した。

## 区切り6: 正規スタートアップの文字列・局所変数処理

- 文字列等値判定、空文字列判定、末尾文字取得、右側切出しを追加した。
- 局所変数の間接アクセスがリターンスタック上のアドレスではなく格納値をデータ領域のアドレスとして扱っていたため、アクセスポインタでリターンスタック上の位置を保持するようにした。関連する2バイト・4バイト・8バイトの読み書きに対応した。
- 局所文字列の切出しやShift-JISの末尾文字のテストを追加した。`dotnet build` は成功し、途中時点の回帰テストは37/38件成功、失敗1件は正規スタートアップの未登録命令によるものだった。
- `hello` / `variables` の正規スタートアップはさらに進んだが、最後の確認時点では未登録命令 `0x011E` で停止した。対応を続ける。

## 区切り7: 正規スタートアップ完走

- スタック上の2値の交換、メモリクリア、文字列サイズ変更、および起動時のセキュリティモード状態の設定を追加した。データ領域とMコード領域のアドレスを区別してクリアする。
- 正規版コンパイラで再生成した `hello` / `variables` を含む5件を別プロセスで実行した。すべて終了コード0、標準出力は対応する参照ファイルとバイト単位で一致した。
- この時点の比較は手動のプロセス実行である。自動回帰テストの追加と既存テストの最終確認を続ける。セキュリティモードは状態の切替えのみで、未実装のOSリソース操作が利用可能になったことを意味しない。

## 区切り8: 自動回帰と最終確認

- 5つのfixtureを別プロセスで実行し、終了コード0と参照ファイルへの標準出力のバイト単位完全一致を検証するテストを追加した。比較結果は `hello` 14バイト、`variables` 15バイト、`binarysearch` 302バイト、`bubblesort` 9871バイト、`insertsort` 3191バイトで、すべて一致した。
- データ領域への切替え時に古いリターンスタック参照をクリアするよう修正し、スタック移動後の局所変数アクセスと切替えの回帰テストを追加した。
- `dotnet build .\tests\McodeLoaderTests.csproj --no-restore --nologo -m:1` は警告0、エラー0で成功した。ビルド済みテストDLLを90秒のタイムアウト付きで実行し、**48/48件成功**した。異常系テストの読込みエラーと命令トレースは標準エラーに出力される。
- `dotnet run --no-restore --project .\tests\McodeLoaderTests.csproj` は途中で無出力のまま停止したため、上記のビルド済みDLLを直接実行して検証した。
- 今回の完了範囲は正規コンソール用ランタイム10・シリアル42の5サンプルである。シリアル46の旧サンプルは拒否され、未実装命令やOSリソース操作を含む全面互換を保証するものではない。
